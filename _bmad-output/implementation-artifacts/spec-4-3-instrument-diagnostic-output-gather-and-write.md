## Intent

**Problem:** The gather (`grid_collect`) and NetCDF-write phases in `Main/mpplib/mod_ncout.F90` carry zero DEBUG-gated timing, so I/O-rank gather time, write time, and wait time cannot be measured separately across the serial, HDF5-parallel, PnetCDF-parallel, and async-netcdf diagnostic-output write paths.

**Approach:** Wrap the gather/write/wait call sites in `write_record_output_stream` (fires on every diagnostic write event) and the `writevar2d_output_stream`/`writevar3d_output_stream` routines in `time_begin`/`time_end`, labels `io_gather_hist`/`io_write_hist`/`io_wait_hist` per AD-17, aggregated at the per-event loop level. Verify DEBUG/non-DEBUG compile across GNU/Intel/NVHPC; runtime-verify serial and HDF5-parallel via a hand-modified fixture, plus a second `--enable-pnetcdf` build to runtime-verify PnetCDF-parallel.

## Design Notes

**Tight per-call wraps, not a loop-body-timer violation.** `write_record_output_stream`'s natural call sites sit inside `do ivar = 1, outstream(istream)%nvar` (4398-4528). The never-instrument-inside-a-loop-body rule is about not timing fragments of unrelated per-iteration logic, not about never calling `time_begin`/`time_end` from code that happens to execute inside a loop — each of `io_gather_hist`/`io_write_hist`/`io_wait_hist` wraps only its own single subroutine call (`grid_collect`/`outstream_writevar`/`outstream_sync`) at that call's own entry/exit, invoked once per iteration, exactly as `mod_output.F90`'s existing timer wraps its own driver call at entry/exit. This is the only design that satisfies AC #1 — a single wrap around the whole loop would report identical totals for gather, write, and wait, not separated numbers. (Renegotiated 2026-08-23; see the frozen Boundaries text and the 2026-08-23 bmad-review correction entry in the Spec Change Log.)

**HDF5-parallel and PnetCDF-parallel need two builds, not one.** They select the same write branch at compile time via mutually exclusive macros (`NETCDF4_HDF5` vs `PNETCDF`), gated by the same runtime `do_parallel_netcdf_out` flag — so verifying all three paths means one fixture run under three separately-built binaries, not one build exercising three runtime branches.
