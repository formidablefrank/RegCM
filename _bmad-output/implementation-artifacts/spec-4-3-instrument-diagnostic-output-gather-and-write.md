## Intent

**Problem:** The gather (`grid_collect`) and NetCDF-write phases in `Main/mpplib/mod_ncout.F90` carry zero DEBUG-gated timing, so I/O-rank gather time, write time, and wait time cannot be measured separately across the serial, HDF5-parallel, PnetCDF-parallel, and async-netcdf diagnostic-output write paths.

**Approach:** Wrap the gather/write/wait call sites in `write_record_output_stream` (fires on every diagnostic write event) and the `writevar2d_output_stream`/`writevar3d_output_stream` routines in `time_begin`/`time_end`, labels `io_gather_hist`/`io_write_hist`/`io_wait_hist` per AD-17, aggregated at the per-event loop level. Verify DEBUG/non-DEBUG compile across GNU/Intel/NVHPC; runtime-verify serial and HDF5-parallel via a hand-modified fixture, plus a second `--enable-pnetcdf` build to runtime-verify PnetCDF-parallel.

## Boundaries & Constraints

**Always:** Use labels exactly `io_gather_hist`/`io_write_hist`/`io_wait_hist` (AD-17) — not `rst`/`clm`, Story 11.2's scope. Follow Convention A (matches `mod_output.F90`): `mod_ncout.F90:27` already has a bare, unconditional `use mod_service`, so new timers use explicit `integer(ik4), save :: <name> = 0` index vars in `#ifdef DEBUG` blocks. In `write_record_output_stream`, wrap the entire `do ivar` loop (4348–4471) as one aggregate per-event timer, not per-variable. Force `do_parallel_netcdf_out=.true.` in any runtime-verification fixture copy — every shipped fixture sets it `.false.`. Runtime-verify HDF5-parallel and PnetCDF-parallel via two separately configured builds against the same fixture (compile-time mutually exclusive). `io_wait_hist` wraps `outstream_sync`'s enqueue call only (4469) — document that it measures enqueue latency, not async-worker completion. Record Build/Test/Numerical/Performance evidence in the commit/PR description, stating which path(s) are build- vs. runtime-verified.

**Ask First:** Before absorbing scope to fix any pre-existing bug surfaced while constructing the fixture or the `--enable-pnetcdf` build — this story instruments and gathers evidence only. ## Design Notes

**Loop-body aggregation, not a rule violation.** `write_record_output_stream`'s natural call sites sit inside `do ivar = 1, outstream(istream)%nvar` (4348-4471) — the never-instrument-inside-a-loop-body rule is satisfied by timing the whole loop as one per-event unit, mirroring how `mod_output.F90`'s existing timer wraps its entire driver rather than each stream it dispatches to.

**HDF5-parallel and PnetCDF-parallel need two builds, not one.** They select the same write branch at compile time via mutually exclusive macros (`NETCDF4_HDF5` vs `PNETCDF`), gated by the same runtime `do_parallel_netcdf_out` flag — so verifying all three paths means one fixture run under three separately-built binaries, not one build exercising three runtime branches.
