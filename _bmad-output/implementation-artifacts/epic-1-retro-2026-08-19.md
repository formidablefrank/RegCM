## Findings

### Cross-story (visible only reading the epic as a whole)

**F1 — `Testing/EUR12_namelist.in` doesn't match the namelist that produced the baseline it documents.** *[fix now]*
`Testing/EUR12_namelist.in:56,66` (`gdate2`/`mdate2 = 2009090800`, a 7-day window) mirrors the untouched canonical `$FAST` file — but the namelist that actually ran and produced the promoted baseline, `RegCM-data/EURR12/story1-2/namelists/EUR12_story1-2_run_nproc-196.in:45,55`, used `gdate2`/`mdate2 = 2009090200` (1 day), confirmed independently by the promoted restart file's own name, `EURR-12_SAV.2009090200.nc`, and by the raw Slurm stdout log (`build-logs/1-2-eur12-twin-run-n196-52648082.out`). Story 1.4's own Verification `diff` command compared `Testing/EUR12_namelist.in` against the *canonical* file (which shares the same wrong window), so the check passed without ever validating against the run that generated the evidence it's meant to document. Neither of Story 1.4's two internal review loops caught this, nor did my own independent re-verification during the gate decision — both compared against the same wrong reference. Root cause: Story 1.2 truncated the date window via `sed` to fit `dcgp_qos_dbg`'s 30-minute cap (Design Notes, `spec-1-2-...md:69`); Story 1.4 copied from the untruncated canonical file instead of the namelist that actually ran.
*Upstream lesson:* a "reference copy of the fixture" claim needs to be checked against the artifact that produced the *evidence*, not the artifact the evidence is nominally "of" — those diverged here and the spec's own boundary language ("copies the `$FAST` canonical file's domain/physics parameters") pointed at the wrong one.

**F2 — `project-context.md` still tells every future agent the regression tool doesn't work.** *[fix now]*
`_bmad-output/project-context.md:134` — "⚠️ There is no working automated regression-diff tool in this repo today" — survived unchanged and unflagged through all four stories' "update project context" commits (`647a9a3e7`, `f50ff8c16`, `8343703bc`, plus my own Story 1.4 edit to the adjacent line 132), even though Epic 1's entire purpose, per its own `epic-1-context.md:25` success criterion, is exactly the opposite: "the regression-diff tool becomes the default regression-evidence method for every subsequent story in the program, replacing manual comparison." This is always-loaded context — every future session is told to do manual NCO/CDO comparison and explicitly instructed not to claim a working command exists.
*Upstream lesson:* a story that syncs one line of a shared, always-loaded file should scan the surrounding section for banners its own change has just outdated — a pure line-diff review (which is what happened four times here) doesn't surface a contradiction two paragraphs away.

**F3 — `PROMOTION_MANIFEST.jsonl`'s recorded commit isn't the commit that built the promoted binary.** *[defer]*
`manage_baseline.py`'s `git_commit()` runs `git rev-parse HEAD` at *promote* time — the manifest records `5f4ea46b3` (2026-08-19). The binary that actually produced the promoted `.nc` files reports `GIT Revision: 39f20-dirty` (per Story 1.2's own Build evidence, `spec-1-2-...md:76`) — commit `39f2085aa`, dated 2026-07-06, six weeks before Story 1.1 even began, plus unrecoverable uncommitted local changes. This gap in the tool's design was invisible through Stories 1.1–1.3 because none of them ever called `promote` for real; Story 1.4 is the first to exercise it in anger, and exposed it.
*Upstream lesson:* "commit at promotion time" and "commit that built this data" are two different facts; a tool whose stated purpose is reproducibility provenance (AD-9) should capture the second, not the first — or record both, distinctly labeled.

**F4 — AD-12's `nproc=1`/`nproc=4` minimum pair is genuinely verified for the ATM stream only.** *[defer, already tracked]*
Both Story 1.1 and Story 1.2 hit the identical `Main/mod_lm_interface.F90:930` DEBUG-build crash on `test_001.in` immediately after ATM's t=0 flush, leaving RAD/SRF/STS as zero-record streams that `regression_diff.py`'s `np.array_equal([], [])` reports "exact" vacuously (`compare_variable`, no zero-record guard). Documented explicitly in both stories' specs and `deferred-work.md`; not fixed in either. This means the epic's own foundational claim — "AD-12's mandated pair is verified" — holds fully only at `nproc=196` (EUR12, which is the *added* coverage, not the *required minimum*).
*Upstream lesson:* when a verification story's evidence quality varies by stream/count, say so in the AC itself next time (e.g. split "verified end-to-end" from "verified for the ATM stream"), not only in a Caveat paragraph a skimming reader can miss.

**F5 — `regression_diff.py`'s vacuous-zero-record gap is the root cause behind F4 and was deferred twice, never fixed.** *[defer, already tracked]*
Found in Story 1.1, confirmed recurring in Story 1.2, both times ruled out of scope ("this story verifies existing tool behavior, it doesn't harden it"). Correct call for either individual story — but three of the epic's four stories now carry evidence partly built on a tool gap nobody owns fixing.

**F6 — `manage_baseline.py`'s baseline directory is keyed by `nproc-<N>` only, no fixture identifier.** *[defer]*
Harmless with exactly one fixture promoted (EUR12). A second fixture promoted at the same `nproc` (e.g. a future coupled-build fixture at `nproc=196`) would silently interleave its files into EUR12's directory — `cmd_promote` has no fixture-scoping concept at all.

**F7 — `PROMOTION_MANIFEST.jsonl` records no build-flavor/configure-flag information.** *[defer]*
`Testing/EUR12_namelist.in`'s `&clm_inparm` groups only take effect under a `-DCLM45`/`-DCLM` build (silent BATS fallback otherwise, per the file's own header comment) — but nothing in the promotion manifest records which build flavor produced or should compare against a given baseline.
