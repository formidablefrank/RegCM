## Deferred from: code review of 1-2-instrument-kpp-chemistry-integration (2026-08-11)

- Shared DEBUG timer registry in `Main/mpplib/mod_service.F90` (`maxnsubs = 100`) has no bounds check in `time_begin` (`mod_service.F90:165-183`): once `n_of_nsubs` exceeds 100, `time_bt(indx)`/`info_serial(indx)` etc. are written out of bounds — an abort under `-fcheck=bounds` (GNU `--enable-debug` builds add this flag) or silent corruption otherwise. A tree-wide grep found ~135 `call time_begin(` sites already present across `Main/` before this story's 2 additions (`cb6_integrate`, `cbmz_integrate`), spanning dynamics, advection, radiation, PBL, multiple alternative cumulus/ocean/land-surface schemes, and chemistry support routines. Not all sites are reachable in a single run (several are mutually-exclusive alternative physics schemes selected by namelist), but land/ocean cumulus scheme selection (`icup_lnd`/`icup_ocn`) can activate more than one scheme at once, and a full-physics production configuration (dynamics + radiation + PBL + cumulus + microphysics + land surface + chemistry) plausibly registers well past 100 distinct labels. This independently substantiates a risk story 1.2's own Task 4 already flagged as unverified at runtime ("Sanity-check `n_of_nsubs` stays under `maxnsubs = 100` cap"). A fix (e.g. `if (n_of_nsubs >= maxnsubs) call fatal(...)` in `time_begin`, mirroring the existing `indx < 0` check already present in `time_end`) is out of scope for story 1.2 — `mod_service.F90` is shared infrastructure used by 40+ files, not owned by this story's two integrator files.
